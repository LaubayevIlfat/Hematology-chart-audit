# Страница «Аудит истории болезни»

Claude Artifact: загрузка PDF истории болезни, извлечение текста, закрытие типовых идентификаторов, двухэтапная экспертиза по правилам навыка, сохранение в Word (.docx), `.md` или копирование.

- `template.html` — исходник страницы (с меткой `__SKILL_JSON__` вместо текста навыка).
- `build.py` — подставляет в шаблон актуальные `SKILL.md`, `references/*.md` и текст шаблона заключения, создаёт `page.html` (в репозитории не хранится).
- Публикация: Artifact с `capabilities {"sample": {}, "downloads": true}`. Запрос к Claude идёт с аккаунта зрителя и расходует его лимит.

Как устроено:
1. PDF читается в браузере (pdf.js 3.11.174, только текстовый слой; сканы не распознаются).
2. Автоматически закрываются ИИН (12 цифр), телефоны, почта, номера документов; остальное пользователь закрывает вручную и подтверждает галочкой.
3. Лимит одного запроса 256 КиБ в байтах UTF-8. Текст, помещающийся в запрос вместе с навыком (порядка 80 000 знаков кириллицы), разбирается целиком. Более длинный (до 800 000 знаков) сначала сжимается по частям в выжимку с дословным сохранением доз, времени и значений; в отчёте об этом есть пометка. При сжатии могут теряться детали.
4. Часть 1 (шапка, хронология, разделы аудита, находки) и часть 2 (системность, вопросы, рекомендации, источники, проект заключения) выполняются отдельными запросами.
5. Word-файл собирается в браузере (JSZip, вручную составленный OOXML): стили заголовков, таблицы, цветные коды находок, колонтитул с нумерацией.

Проверено: логика страницы на подставных ответах, извлечение текста из PDF, закрытие идентификаторов, сборка .docx (открывается python-docx, XML корректен). Не проверено: реальный запрос к Claude на настоящей истории, открытие .docx непосредственно в Word, качество отчёта на длинных историях после сжатия.
